Группа команд `/logging` позволяет администраторам назначать конкретные текстовые каналы для получения подробных журналов аудита по разным категориям активности сервера.

Все команды `/logging` требуют разрешения **Administrator**.

---

## Категории журналов

| Категория | Регистрируемые события |
|----------|--------------|
| `members` | Вступления, уходы, баны, кики участников, изменения ников, изменения ролей |
| `messages` | Редактирования сообщений, удаления сообщений, массовые удаления |
| `channels` | Создание, удаление каналов, изменения имени / темы / разрешений |
| `roles` | Создание, удаление ролей, изменения разрешений, изменения цвета |
| `voice` | Вход, выход, перемещения по голосовым каналам, муты, отключения звука |
| `server` | Изменения имени сервера, иконки, региона и настроек |
| `moderation` | Все действия, выполненные командами `/mod` |
| `security` | События безопасности (полезно как выделенный журнал аудита наряду с реальным каналом оповещений) |

---

## Команды

### `/logging set`

Назначить канал для получения журналов определённой категории.

| Опция | Тип | Обязательно | Описание |
|--------|------|:--------:|-------------|
| `category` | Choice | ✅ | Категория журнала |
| `channel` | TextChannel | ✅ | Канал для публикации журналов |

Каждая категория сопоставляется с одним каналом. Повторный запуск `/logging set` для той же категории заменяет предыдущее назначение.

**Примеры:**
```
/logging set category:messages channel:#message-logs
/logging set category:moderation channel:#mod-audit
/logging set category:security channel:#security-log
```

---

### `/logging remove`

Прекратить отправку журналов для определённой категории.

| Опция | Тип | Обязательно | Описание |
|--------|------|:--------:|-------------|
| `category` | Choice | ✅ | Категория журнала для удаления |

---

### `/logging status`

Отобразить все текущие назначения каналов журналирования для этого сервера.

---

### `/logging test`

Опубликовать образец карточки журнала в назначенный канал для категории, чтобы вы могли проверить форматирование и разрешения перед тем, как полагаться на него.

| Опция | Тип | Обязательно | Описание |
|--------|------|:--------:|-------------|
| `category` | Choice | ✅ | Категория для теста |

---

## Примеры карточек журнала

### Вступление участника
```
👥  Member Joined
────────────────────────────────
User:         @newmember (123456789)
Account age:  3 days ⚠️
Joined at:    <timestamp>
Member count: 247

─  Nightfall Security  •  Member Logging
```

### Удаление сообщения
```
💬  Message Deleted
────────────────────────────────
Author:   @user (987654321)
Channel:  #general
Content:  "deleted message content here"
Deleted:  <timestamp>

─  Nightfall Security  •  Message Logging
```

### Действие модерации
```
⚖️  Member Banned
────────────────────────────────
Target:     @user (111222333)
Moderator:  @mod (444555666)
Reason:     Repeated spam violations

─  Nightfall Security  •  Moderation Logging
```

## Требования к разрешениям

Чтобы Nightfall мог публиковать журналы, ему нужны следующие разрешения в канале журнала:

- `View Channel`
- `Send Messages`
- `Embed Links`

Если что‑либо из этого отсутствует, запись журнала молча отбрасывается.

---

## Советы

- Создайте **приватную категорию журналов**, видимую только администраторам, с одним каналом на каждый тип журнала
- Используйте журналирование `security` как постоянный след аудита отдельно от реального канала оповещений
- Журнал `moderation` автоматически заполняется всеми командами `/mod` — дополнительная настройка не требуется
- Используйте `/logging test`, чтобы проверить каждый канал перед тем, как полагаться на него
