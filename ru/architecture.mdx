Nightfall построен на **отказоустойчивой многопроцессной архитектуре**, разработанной для поддержания бесперебойной работы и постоянной защиты даже при высокой нагрузке или неожиданных сбоях. Каждая крупная задача выполняется в отдельном изолированном процессе.

---

## Обзор процессов

### Gateway

Gateway обрабатывает live‑соединение с Discord. Он получает события от Discord, направляет их к соответствующим воркерам и обрабатывает slash‑ и prefix‑команды. Gateway — единственный процесс, который напрямую взаимодействует с API Discord.

### Воркеры событий

Воркеры событий выполняют основную работу по обработке — оценку правил AutoMod, запуск обнаружения anti‑nuke и anti‑raid, а также диспетчеризацию модерационных действий. Несколько воркеров работают параллельно, а входящие события распределяются между ними по стратегии наименее загруженного. Это гарантирует, что всплеск событий в одной области не задерживает обработку в другой.

### Воркер базы данных

Все записи в базу данных направляются через единый выделенный воркер посредством очереди. Это безопасно сериализует записи без блокировок, обеспечивая целостность данных даже при одновременном поступлении множества событий.

### Планировщик

Планировщик выполняет периодические фоновые задачи с настраиваемым интервалом:

- Проверка истечения премиум‑подписок (с DM‑напоминаниями)
- Отправка DM со скидкой после пробного периода для партнёрских пробников
- Очистка устаревших записей
- Регулярные проверки состояния

### Супервизор

Супервизор наблюдает за всеми остальными процессами. Если какой‑либо процесс неожиданно завершается, супервизор автоматически перезапускает его с использованием экспоненциальной задержки — прогрессивно увеличивая интервал между попытками перезапуска, чтобы избежать флуда. Такое самовосстановление означает, что временные сбои (сетевые проблемы, ошибки API) устраняются без ручного вмешательства.

## Почему многопроцессная архитектура?

Однопроцессный бот уязвим: одна блокирующая операция, утечка памяти или сбой роняет всё. Архитектура Nightfall изолирует каждую задачу:

| Преимущество изоляции | Пример |
|------------------|---------|
| Gateway остаётся отзывчивым | Медленная оценка AutoMod не задерживает ответы на команды |
| Безопасность базы данных | Никаких конфликтов записи даже при множестве одновременных событий |
| Локализация сбоев | Сбой воркера событий устраняется без влияния на gateway |
| Независимое масштабирование | Больше воркеров событий могут обрабатывать большие объёмы событий |

## Функции надёжности

| Функция | Описание |
|---------|-------------|
| **Самовосстанавливающийся супервизор** | Аварийно завершённые процессы автоматически перезапускаются с экспоненциальной задержкой |
| **Маршрутизация к наименее загруженному** | События распределяются самому свободному воркеру |
| **База данных в режиме WAL** | Безопасное одновременное чтение во время записи |
| **Постоянные сессии верификации** | Перезапуски бота не аннулируют текущие верификации участников |
| **Постоянные компоненты кнопок** | Панели верификации и премиум сохраняются после перезапусков |
