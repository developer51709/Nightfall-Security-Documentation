## How threats are detected

Nightfall uses **sliding‑window rate counters** to track event frequency in real time. A counter per guild tracks how many events of each type (channel deletions, role deletions, joins, bans, mentions) occurred in the last 60 seconds. When a counter exceeds the configured threshold, an alert fires immediately.

This approach is:
- **Fast** — no database overhead per event; counters live in memory
- **Accurate** — a true 60‑second rolling window rather than a fixed time bucket
- **Per‑guild** — each server has its own independent counters and thresholds

## Alert cards

When a threshold is exceeded, Nightfall posts a formatted alert to your configured alert channel:

```
🛡️  Security Alert — ANTI_RAID
────────────────────────────────────────
Join surge detected: 14 joins in the last 60 seconds.
Threshold: 10 per minute.

👥  Actor:    @username (123456789)
⏰  Detected: just now

─  Nightfall Security  •  Severity: HIGH  •  Defensive mode only
```

Severity levels:

| Level | Meaning |
|-------|---------|
| **Low** | Minor anomaly — informational |
| **Medium** | Suspicious activity |
| **High** | Active threat detected |
| **Critical** | Severe coordinated attack |

## Defensive‑only model

Nightfall is designed exclusively to **protect**, never to harm:

- ✅ Alert moderators via the configured alert channel
- ✅ Take configurable automated actions (kick, ban) on detected threats
- ✅ Engage soft locks to pause destructive‑action tracking
- ❌ Never initiates offensive actions against other servers or users
- ❌ Never takes action beyond what the server administrator has explicitly configured

## Threshold presets

The `/setup` wizard offers three threshold presets as a starting point:

| Preset | Joins/min | Channel deletes/min | Role deletes/min | Bans/min | Mentions |
|--------|-----------|--------------------|-----------------|---------|---------| 
| **Strict** | 5 | 2 | 2 | 3 | 5 |
| **Balanced** | 10 | 3 | 3 | 5 | 8 |
| **Relaxed** | 20 | 6 | 6 | 10 | 15 |

All thresholds can be fine‑tuned at any time with `/security config`. See the [Security command reference](/commands/security) for all available options.

---

## Whitelist

Trusted administrators, bots, or roles can be exempted from all detection. Whitelisted entities' actions do not increment any rate counters.

Manage exemptions with the `/whitelist` command. See the [Whitelist reference](/commands/whitelist) for permission requirements and usage.

<Warning>
  Whitelisting is powerful — a whitelisted role exempts every member who holds it. Avoid whitelisting broad roles or you will effectively disable protection for those members.
</Warning>
